> Если я хочу подписать данные используя EdDSA, то мне нужно предварительно
> сгенерировать ключи (приватный и публичный). Вопрос - эти ключи обязательно
должны быть сгенерированы на основе некоторой элиптической кривой?

Да, это обязательное условие. Использование эллиптической кривой — это не
просто рекомендация, а фундаментальная основа алгоритма EdDSA (Edwards-curve
Digital Signature Algorithm).

Само название алгоритма прямо указывает на это: Edwards-curve Digital Signature
Algorithm. Без эллиптической кривой EdDSA работать не будет.

Как это связано с ключами?

Ключи в EdDSA генерируются и существуют именно в контексте эллиптической кривой:

    Приватный ключ (seed): Это просто случайная строка бит (например, 32 байта
для Ed25519). Однако сам по себе он не является «ключом» в математическом
смысле. Его основное назначение — служить детерминированным источником для
генерации секретного числа и одноразовых значений.

    Публичный ключ: Это точка на эллиптической кривой. Он вычисляется путем
умножения секретного числа (полученного из приватного ключа) на генераторную
точку G этой кривой: PublicKey = privateKey * G.

Весь процесс подписи и проверки опирается на математические операции именно в
группе точек этой эллиптической кривой.

Какие кривые используются?

EdDSA не работает с произвольными эллиптическими кривыми. Стандарт (RFC 8032)
определяет его для двух конкретных, хорошо изученных и оптимизированных кривых:

    edwards25519 (для варианта Ed25519)
    edwards448 (для варианта Ed448)

Таким образом, хотя ваш приватный ключ может выглядеть как обычный набор
случайных байт, он обязательно привязан к одной из этих кривых, и без нее весь
алгоритм теряет смысл.




> Не вижу доступных кривых для EdDSA в выводе openssl ecparam -list_curves.

В openssl ecparam -list_curves кривых для EdDSA не будет. Это нормально, и вот
почему.

Почему EdDSA нет в списке ecparam

openssl ecparam работает с параметрами эллиптических кривых в форме
Вейерштрасса — именно они используются в ECDSA и ECDH. Это кривые вида
secp256k1, prime256v1, brainpoolP256r1 и т.п.

EdDSA же использует скрученные кривые Эдвардса (edwards25519, edwards448). В
OpenSSL они реализованы не как набор параметров EC, а как отдельные типы
ключей:
    ED25519
    ED448

Поэтому они не появляются в ecparam -list_curves. То же самое, кстати, с X25519
для ECDH — его тоже нет в этом списке.

Как проверить, что EdDSA поддерживается

Сначала посмотрите версию OpenSSL:
openssl version

Поддержка Ed25519/Ed448 появилась в OpenSSL 1.1.1. Если версия старше — EdDSA
не будет.

Затем выведите список алгоритмов публичных ключей:

# OpenSSL 3.x
openssl list -public-key-algorithms
# OpenSSL 1.1.1 (может отличаться)
openssl list -public-key-methods

Ищите там ED25519 и ED448. Можно отфильтровать:

openssl list -public-key-algorithms | grep -i ed

Также можно посмотреть алгоритмы подписи:

openssl list -signature-algorithms | grep -i ed

Как сгенерировать ключи для EdDSA

Никакого выбора кривой через ecparam не нужно. Просто указываете алгоритм:

# Приватный ключ Ed25519
openssl genpkey -algorithm ED25519 -out ed25519.key

# Публичный ключ из приватного
openssl pkey -in ed25519.key -pubout -out ed25519.pub

Для Ed448:

openssl genpkey -algorithm ED448 -out ed448.key
openssl pkey -in ed448.key -pubout -out ed448.pub

Подпись и проверка

EdDSA — однораундовый алгоритм, поэтому используется pkeyutl с флагом -rawin:

# Подписать файл
openssl pkeyutl -sign -inkey ed25519.key -rawin -in message.txt -out signature.bin

# Проверить подпись
openssl pkeyutl -verify -pubin -inkey ed25519.pub -rawin -in message.txt -sigfile signature.bin

Итог
  - ecparam -list_curves показывает только кривые для ECDSA/ECDH.
  - EdDSA (Ed25519/Ed448) — отдельные алгоритмы, их кривые «вшиты» внутрь.
  - Чтобы работать с EdDSA, используйте genpkey -algorithm ED25519 (или ED448).
  - Если в openssl list этих алгоритмов нет — обновите OpenSSL или проверьте,
    что он собран с их поддержкой.
